                        `--dangerously-bypass-approvals-and-sandbox` and stays
                        people-only. A named Codex requirements file that is
                        missing, empty or unreadable refuses the Codex launch
                        (400) and does not fall through to bypass. Klaudia
                        takes `default` and `bypass` only (its `acceptEdits`
                        is an alias for its default autonomous mode, so
                        `accept_edits` is refused).
  --account ACCOUNT     Run the session under a named Claude Code subscription
                        account (a name from the engine's
                        ENGINE_AGENT_CLAUDE_ACCOUNTS). Omitted uses the
                        engine's default account. Claude Code templates only;
                        an unknown name is refused, never started on the
                        default login.
  --resume RESUME       Continue a previous conversation of the template's
                        agent CLI instead of starting a new one: its own
                        conversation id, mapped to `claude --resume <id>`,
                        `codex resume <id>`, `opencode --session <id>` or
                        `klaudia --resume <id>`. A Claude Code (or Klaudia)
                        session Vogt started fresh has the engine session id
                        (`engine_session_id`) as its conversation id, so a
                        session lost to a restart can be resumed by that. The
                        engine starts a resumed conversation in the directory
                        its transcript records (when inside the workspace), so
                        one begun under a worktree or a parent folder resumes
                        from any project. Requires `template`; letters, digits
                        and . _ - only, never a leading dash.
  --name NAME           Session name. Derived from the subject if omitted.
  --model MODEL         Model id for the agent CLI this template runs, e.g.
                        'gpt-5.6' or 'claude-sonnet-4-5'. Omitted means the
                        CLI's own default. Requires `template`: a plain shell
                        has no model. A template that cannot be told which
                        model to use refuses rather than ignoring this.
  --effort EFFORT       Reasoning effort for the agent CLI, e.g. 'low' /
                        'medium' / 'high'. Omitted means the CLI's own
                        default. Requires `template`: a plain shell has no
                        effort to set, so do not volunteer one for a terminal
                        that runs no agent.
  --autopilot, --no-autopilot
                        Keep the agent working unattended: its brief tells it
                        to carry on when its next step needs no person,
                        stopping only when it is blocked on a person (reported
                        with session_report_blocked) or no unblocked work is
                        left (then it prints `AUTOPILOT: DONE`). The engine
                        also re-prompts it whenever it stops at its prompt
                        with work left, and its idle policy leaves it awake.
                        Omitted means on for an agent template started with a
                        `task`, off otherwise; `false` turns it off.
  --role {worker,oversight}
                        `oversight` nominates the session to supervise others
                        (drive rollouts, check on and revive worker sessions):
                        it is pinned awake, so it comes back by itself after a
                        redeploy, and the GUI lists it first. `worker`
                        (default) is every other session. Only a person starts
                        an oversight session; an agent caller is refused.
                        Change it later with session.set_role.
  --from-handoff FROM_HANDOFF
                        Start a fresh session from a work item's hand-off
                        comment: the work item ref (e.g. WI-7). Refused when
                        that item has no hand-off comment, and refused when
                        `work_item` is also given and names a different item.
                        The brief carries the latest hand-off.
  --review-of REVIEW_OF
                        Start a reviewer on this work item (e.g. WI-7) instead
                        of a worker. The brief checks the diff named by the
                        item's latest hand-off against the item's own
                        acceptance criteria, and it does not carry the work
                        on. Refused without a work item — a review is of an
                        item — and when `work_item` or `from_handoff` names a
                        different one.
  --budget BUDGET       Limits the engine enforces on this session (C7): a
                        soft warning as one is approached, then hibernation
                        (trigger `budget`) when one is reached. Omitted means
                        the default for an agent template started with a
                        `task` as a worker — 120 turns and 90 minutes of wall
                        clock, no context limit — and no budget otherwise. An
                        empty object sets no limits, which is how a start
                        declines the default.
  --worktree, --no-worktree
                        Start the session in a git worktree of its own rather
                        than in the project's shared checkout (WI-1298). The
                        engine cuts the worktree from the project's
                        integration branch — `agent_policy.base_branch` when
                        the project states one, otherwise `main` — onto a new
                        branch `<work item>-<session>` (or
                        `<project>-<session>` when no work item is given), and
                        the session's working directory is that worktree. The
                        shared checkout is never written to, so a dirty tree
                        there cannot leak into the session and the session
                        cannot disturb it. Requires a project, or a work item
                        that belongs to one. Unset, the purpose's dispatch
                        profile decides (WI-1323), and with no purpose the
                        session opens in the project's checkout, as `false`
                        does. Cannot be combined with `cwd` (WI-1671).
                        Recorded on the audit row.
  --cwd CWD             Open the session in this existing directory instead of
                        the project's registered checkout (WI-1671). Use it
                        when a worktree already exists and `worktree=true`
                        cannot cut a new one — a private origin the engine
                        cannot fetch, for example. The path must exist, must
                        sit under the workspace's `Active/` directory (the
                        parent of the project's checkout), must not be inside
                        that checkout (a subdirectory shares its git toplevel;
                        a linked worktree nested under it does not), and must
                        be a git worktree of the same repository (the same
                        `commondir`). Anything else is refused, and so is
                        combining it with an explicit `worktree=true`. A
                        purpose profile that would have set `worktree` does
                        not, when `cwd` is given. Recorded as the session's
                        cwd.
  --reason REASON       Why this write is being made (audited).
  --purpose {implement,implement-careful,review,mechanical,investigate,design}
                        What the session is for (WI-1323, design §2.4):
                        implement, implement-careful, review, mechanical,
                        investigate or design. The deployment's dispatch
                        profile for it fills template, model, effort, budget,
                        worktree, repo_map and autopilot wherever this start
                        leaves them unset; a value given here wins and is
                        audited as an override. Recorded on the session.
