Design guardrails

Rules for the restructured desktop shell and the mobile app. They exist so the next screen anyone adds still looks and behaves like Vogt — and so the product keeps telling the truth about what it knows.

1 · Principles the UI must not break

These come from the product's own principles. Every one of them is a design constraint, not a backend detail.

  1. Every answer carries provenance and freshness. A number without an age is a bug. "verified 2m ago from GitHub" and "declared 3 weeks ago, never confirmed" must never render the same.
  2. Declared and observed stay visually distinct. Trust is a badge on every row and card: declared is neutral, observed is amber, collected is blue.
  3. Reports, never enforces. No screen may block an action because something is non-compliant, stale or drifting. Colour says what the view is; it never gates.
  4. Empty is two different answers. "Nothing to say" and "not collected" get different copy. If a collector didn't run, the empty state says so — an empty list is never dressed as good news.
  5. Every write takes a reason. Moves, suppressions, adoptions, conversions and approvals all collect a reason inline and refuse without one. The refusal shows Vogt's own sentence, unedited, in monospace.
  6. Agents are visible actors. When a session writes, the UI names it (session:clip-fix-3), and an approval happens on the approver's credential.

Amber is reserved. It means "this answer is older or less trusted than it looks" — never decoration. Red is reserved for needs-you and failure. One meaning per colour, across every surface.

3 · Type and density

  • One family: ui-sans-serif, system-ui. Monospace (ui-monospace, SFMono-Regular, Menlo) only for machine text: refs, paths, commands, terminal output, Vogt's own error sentences.
  • Desktop scale: 20px surface title · 13–14px body · 12px controls · 11.5px meta · 10.5px badges. Nothing below 10px.
  • Phone scale: 17px screen title · 14–14.5px row title · 12.5px controls · 11.5px meta. Terminal composer is 16px — smaller triggers iOS zoom-on-focus.
  • Rows and cards size to their content. This is the point of the restructure: no fixed --board-card-h tile, no 40px backlog row. Collapsed cards clamp at 3 lines and expand in place.
  • Uppercase + letter-spacing:.06–.1em at 10.5–11px is the only label treatment (column heads, rail group names).
  • Borders 1px, radii 4px (controls) / 6px (cards, sheets) / 8–14px (pills, phone cards). No shadows except sheets, toasts and the phone FAB.

4 · Desktop shell

  • Places, not tabs. A 248px text-first rail holds Board · Backlog · Inbox (Work), Projects · Audit (Estate), Sessions (Machine). Surfaces are not closable; terminals and editors live inside Sessions.
  • No glyph or emoji nav. Active state is a 2px accent bar plus elevated background — never a boxed tile.
  • The rail also carries the running session list (activity dot + continuity mark + name + cwd) and the file tree with search. Both are always available; neither is a modal.
  • Every surface header is the same grammar: title · freshness chip · honesty chip (when relevant) · spacer · view controls · primary action.
  • Filters are chips with an + filter affordance and named saved lenses — never a 4-column grid of selects.
  • Reasons, refusals and quick-create are inline in the surface. A modal over the board counts as leaving the view.

5 · Mobile app

  • Sessions is the first-class citizen. The phone is a steering device: it lands on running sessions, sorted by what needs you. Board and Backlog are for reading, not managing.
  • Four-place bottom bar — Sessions · Inbox · Board · Backlog — at 60px with live counts. No hamburger drawer, no tab-count sheet.
  • A session waiting for input is a card carrying the actual PTY prompt and one-tap answers (y ⏎, ^C). Everything else is a list row.
  • Row actions live in a bottom sheet, one per line at ≥52px. Nothing important behind long-press; nothing at all behind hover.
  • Keep the mod-key row: 44px tall, 52px minimum key width, Ctrl is sticky/armed and chords with the next key.
  • Board shows one state at a time via a pill row. Never stack every column vertically — that made the phone board a mile of page.
  • Keyboard hints are hidden on coarse pointers; touch targets never below 44px.

6 · The notification inbox

  • One unified stream with source filters: GitHub · drift · CI · agent events. It is its own place — never a view toggle inside Audit again.
  • Every row: unread dot · source tag in that source's colour · title · provenance and freshness line · relative age.
  • Actions, all present: archive, convert to work item, open the related item, open a session, snooze, suppress with a reason.
  • The header states sweep coverage. Filtering to a source with no collector shows "Not collected", not an empty list.
  • Drift rows show both sides and take a typed reason to resolve; forge write-back stays additive and forward-only.

7 · Don't

  • Don't invent colours, add gradients, or use amber/red decoratively.
  • Don't add emoji or pictographic glyphs to navigation (the repo's fileIcons.ts emoji set is deliberately not used in these designs).
  • Don't reintroduce fixed row or card heights for windowing convenience.
  • Don't show an aggregate without its age, or a subject without its trust.
  • Don't collect a write without a reason, and don't paraphrase Vogt's refusal text.
  • Don't move a surface behind a closable tab, and don't put a phone action behind hover.

8 · Implementation notes that are not design

  • Content-sized cards mean dropping the windowed-column maths: CARD_HEIGHT/CARD_GAP in Board.tsx and ROW_HEIGHT in Backlog.tsx exist only so a column can compute where a tile goes, and they must match the CSS variables exactly. Change them together or the list skips and repeats.
  • Notifications need their own route rather than ?view=inbox on the audit browser, and the drift read currently on Projects has to feed the same stream.
  • Copy/paste is a PTY and WebView-clipboard problem, not a layout one. The designs only reduce how often you need it (per-block copy, copy on the composer row). One bridge for web, PWA and Capacitor is the actual fix.
  • Nothing here assumes a forge: with GitHub unconfigured, the GitHub and CI sources simply report "not collected".
